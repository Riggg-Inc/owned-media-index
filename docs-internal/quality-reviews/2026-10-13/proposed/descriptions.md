# Descriptions

**Stage:** Package

Descriptions are the second packaging decision after titles. They appear in RSS feeds, podcast apps, YouTube, social posts, and website show notes. A strong description helps the audience decide whether to invest their time.

## Quality Bar

A strong description should:

- Open with a sentence that earns the second sentence
- Establish guest credibility or topic relevance quickly
- Tell the listener what they will learn — specifically
- Include key takeaways, timestamps, or chapter markers where appropriate
- End with a clear CTA (subscribe, visit, follow)
- Make the opening useful on its own and preview it in the actual destination.

## Platform Checks

Do not assume one character limit or preview length covers every podcast app. Check the actual publishing host, field and device before release.

- **YouTube:** Descriptions allow up to 5,000 characters. Put the main promise in the first few lines and inspect desktop and mobile previews. [Official guidance](https://support.google.com/youtube/answer/12948449?hl=en).
- **Spotify:** Show notes support links, headers, lists, paragraphs and line breaks through supported HTML. Other listening platforms can render the same feed differently. [Official formatting guidance](https://support.spotify.com/us/creators/article/formatting-your-show-notes/).
- **Other podcast apps and RSS:** Check current host and destination requirements; verify links, line breaks and the first visible sentence in the actual app. This guide does not establish universal hard limits for these destinations.
- **Website:** Use readable headings, relevant links and a clear next action rather than filling an arbitrary word allowance.

Google Podcasts is not a current publishing destination; Google's [transition announcement](https://blog.youtube/news-and-events/podcast-destination-on-youtube-music/) scheduled its discontinuation in 2024.

### Recommended Working Defaults

Start with a self-contained opening and only the details needed to make an informed listening decision. A 150–300-word draft can be a useful editorial starting point, not a platform guarantee. Use a shorter format when the episode promise needs less explanation. Add accurate timestamps for YouTube chapters when appropriate and check links in the feed's rendered description.
